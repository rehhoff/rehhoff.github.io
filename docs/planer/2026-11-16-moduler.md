# Plan: Opdeling af index.html i filer (10.0.0)

Planlagt og udført af Claude Opus, 2026-11-16. Udfører: Opus, fordi det er en mekanisk flytning uden ændret adfærd, og fordi den skal være færdig, før Fable og Opus arbejder samtidig.

## Mål

Flere modeller skal kunne arbejde samtidig uden at rette i den samme fil. Appen skal fungere nøjagtigt som før, og der indføres intet byggetrin.

## Struktur

| Fil | Indhold |
|---|---|
| `index.html` | Markup med Alpine-direktiver og script-tags |
| `css/app.css` | Farvetokens, temaer og egne klasser (tidligere `<style>`) |
| `js/tailwind.config.js` | Tailwind-opsætning til CDN'et |
| `js/data.js` | Konstanter, nøgler, tabeller (`IZ`, `EFFEKT`, `SF` …), `norm()`, eksempeldata, hashfunktioner |
| `js/beregning.js` | `APP_BEREGNING`: strøm, ΔU, I<sub>z</sub>, fasebalance, kabeltabel, samtidighed, tilgangskabel, effektforslag |
| `js/diagram.js` | `APP_DIAGRAM`: enstregsdiagram, sporing, afbrydere og tændingsdiagram |
| `js/lagring.js` | `APP_LAGRING`: projekter, eksport, import, backup og synkronisering |
| `js/app.js` | `app()`: tilstand, `init()` og resten af brugerfladen. Samler delene med `bland()` |

## Teknik

- Almindelige scripts (ikke ES-moduler), indlæst i rækkefølge før Alpine. De deler globalt scope som før, så markup og funktioner virker uændret.
- Hver fil med metoder definerer en funktion, der returnerer et objekt, fx `const APP_BEREGNING = () => ({ ... })`. `app()` samler dem med `Object.getOwnPropertyDescriptors`, så intet ændres ved kopieringen. Der er kontrolleret for dubletter og getters: ingen.
- Alle `css/` og `js/` hentes med `?v=<APP_VERSION>`, så en ny `index.html` aldrig kører med gamle filer fra browserens cache.
- Ingen ændring af data, nøgler eller `SCHEMA`.

## Test

- `tests/smoke.py` serverer filerne fra disken i stedet for kun `index.html`.
- Røgtesten skal give `OK` før og efter.
- Kontrol af at `?v=` i `index.html` svarer til `APP_VERSION` (tilføjes i røgtesten).
